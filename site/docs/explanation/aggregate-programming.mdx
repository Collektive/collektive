# Building Resilient Systems with Aggregate Programming

## Why these systems are hard to build

Internet of Things deployments, robot swarms, and smart-city infrastructures share a set of uncomfortable properties.
They are made of many **heterogeneous** devices, often resource-constrained, some static and some moving.
Devices fail, join, and leave, and the network topology changes all the time.
Connectivity is not guaranteed either: devices in a field, at sea, or in a disaster area
may only be able to talk to the devices nearby, with no Internet and no central server.

Programming such systems device by device means writing the local rules (what each device senses, computes, and sends)
and hoping that the right global behavior emerges.
Every failure and every topology change has to be anticipated by hand,
and the gap between the local code and the global goal grows with the size of the system.
Ideally, we would like to write a single program that describes the behavior of the whole system,
and let each device run its part.

## Aggregate programming

**Aggregate programming**[^1] is a macroprogramming approach that does exactly that.
The programmer describes the collective behavior as a composition of reusable *collective* functions,
and the framework turns it into the local behavior and the messages of each device.
The resulting systems are:

*Self-stabilizing* means that, whenever inputs and network stop changing, the program converges to the correct result,
whatever state it starts from: the effects of a disruption eventually vanish, without anyone having to reset the system.

### From the field calculus to building blocks

Aggregate programming has its formal roots in the *field calculus*[^3],
a minimal functional language in which programs manipulate *computational fields*:
values spread over the devices of the network, and evolving over time.
Its latest evolution, the *eXchange Calculus*[^6] (XC), unifies state, communication with the neighbors, and domain partitioning
in a single primitive, `exchange`. XC is the calculus implemented by Collektive (see [Aggregate Operators](dsl-descriptions.mdx)).

On top of these primitives, aggregate programming provides *building blocks*[^7]:
self-stabilizing collective functions that recur in most applications.
Gradients and broadcasts propagate information from sources;
collection aggregates it towards sinks;
gossip and leader election let the devices agree on values and coordinators.
In Collektive, they make up the [standard library](standard-library/overview.mdx).

## Where it is used

Aggregate programming has been applied to many coordination problems in distributed systems, including:

- **robot swarms**[^4]: formation control, coverage, clustering, and search and rescue;
- **crowd management**[^5]: density estimation, anomaly detection, and safe dispersal during large events;
- **environmental monitoring**: networks of sensors that estimate pollution, temperature, or the spread of a wildfire;
- **morphogenetic engineering**[^2]: the growth of self-organizing spatial structures, as in the vascular morphogenesis controller built with Collektive.
