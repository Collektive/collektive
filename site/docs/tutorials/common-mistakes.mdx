Aggregate programs look like ordinary Kotlin, but they are executed by a whole network of devices, round after round.
These are the mistakes we see most often, how to recognize them, and how to fix them.
Several of them are caught by the [compiler plugin](../explanation/compiler-plugin.mdx), which reports them as warnings while you build:
do not ignore those.

<Mistake>

## The compiler plugin is not applied {#compiler-plugin}

<Symptom>The program compiles, but fails at runtime with an `AlignmentClashException`.</Symptom>

<Explanation title="Fix">

Apply the Collektive Gradle plugin, see [Getting Started](getting-started.mdx#compiler-plugin-setup).
Without it, Collektive cannot tell its operators apart.

</Explanation>

</Mistake>

<Mistake>

## Computing inside the wrong branch {#wrong-branch}

<Symptom>A value never propagates: typically, a gradient that stays at infinity.</Symptom>

<DoDont>
<Dont label="the source takes the other branch, so it is not a neighbor inside the else">

```kotlin
share(Double.POSITIVE_INFINITY) { d ->
    if (source) 0.0 else (d + metric).neighbors.values.min()
}
```

</Dont>
<Do label="compute through the whole neighborhood first, then select">

```kotlin
share(Double.POSITIVE_INFINITY) { d ->
    val throughNeighbors = (d + metric).neighbors.values.min()
    if (source) 0.0 else throughNeighbors
}
```

</Do>
</DoDont>

<Explanation>

`if` and `when` partition the network: inside a branch, only the devices that took the same branch are aligned.
Use branches to *separate* sub-collectives; to *select* a value, compute the alternatives first.
See [Branches partition the network](../explanation/alignment.mdx#branches-partition-the-network).

</Explanation>

</Mistake>

<Mistake>

## Aggregate operators in loops {#loops}

<Symptom>

An `AlignmentClashException` at runtime, or the compiler warning
*"Aggregate function … is called inside a loop without explicit alignment"*.

</Symptom>

<DoDont>
<Dont label="every iteration produces the same alignment path">

```kotlin
targets.map { target -> distanceTo(localId == target) }
```

</Dont>
<Do label="align each iteration on a value that identifies it on every device">

```kotlin
targets.map { target -> alignedOn(target) { distanceTo(localId == target) } }
```

</Do>
</DoDont>

<Explanation title="More">

See [Loops and `alignedOn`](../explanation/alignment.mdx#loops-and-alignedon).

</Explanation>

</Mistake>

<Mistake>

## Including (or excluding) yourself by mistake {#all-or-neighbors}

<Symptom>Values that do not change, or that only depend on the local device.</Symptom>

<DoDont>
<Dont label="the local entry makes every device see its own old estimate">

```kotlin
(distances + metric).all.values.min()
```

</Dont>
<Do label="in a gradient, the minimum goes through the neighbors only">

```kotlin
(distances + metric).neighbors.values.min()
```

</Do>
</DoDont>

<Explanation>

Choose deliberately between `field.all` (local entry included) and `field.neighbors` (local entry excluded).
Also remember that `neighbors` may be empty: reductions on it return `null` or a neutral element
(see [Field operations](../explanation/standard-library/field-operations.mdx#return-types-depend-on-the-view)).

</Explanation>

</Mistake>

<Mistake>

## Using `evolve` + `neighboring` instead of `share` {#evolve-instead-of-share}

<Symptom>Information propagates slowly, or the compiler warns *"This 'evolve' can be replaced with 'share'"*.</Symptom>

<DoDont>
<Dont label="neighbors receive the value before the update">

```kotlin
evolve(localId) { max -> neighboring(max).all.values.max() }
```

</Dont>
<Do label="neighbors receive the updated value">

```kotlin
share(localId) { ids -> ids.all.values.max() }
```

</Do>
</DoDont>

</Mistake>

<Mistake>

## Sharing a constant with `neighboring` {#constant}

<Symptom>The compiler warns *"This 'neighboring' call uses a compile-time constant"*.</Symptom>

<DoDont>
<Dont label="sends a value that every device already knows">

```kotlin
val ones = neighboring(1)
```

</Dont>
<Do label="only the alignment information is exchanged">

```kotlin
val ones = mapNeighborhood { 1 }
```

</Do>
</DoDont>

</Mistake>

<Mistake>

## Returning or storing fields {#storing-fields}

<Symptom>A compile-time error *"This branch returns a Field"*, or a runtime error from `evolve` or `alignedOn`.</Symptom>

<Explanation>

Fields are only meaningful in the round and in the alignment context in which they were built:
they cannot be returned from branches, stored with `evolve`, or returned from `alignedOn`.

</Explanation>

<Explanation title="Fix">

Build fields before branching, and store collapsed (local) values.
See [Rules of the game](../explanation/fields.mdx#rules-of-the-game).

</Explanation>

</Mistake>

<Mistake>

## Non-serializable shared values {#serialization}

<Symptom>`SerializationException: Serializer for class '…' is not found` at runtime.</Symptom>

<Explanation>

Values sent to neighbors are serialized, unless the network works in memory only.

</Explanation>

<Explanation title="Fix">

Annotate your data classes with `@Serializable`
(and apply the [kotlinx.serialization](https://github.com/Kotlin/kotlinx.serialization) plugin):

```kotlin
@Serializable
data class Candidate(val id: Int, val score: Double)
```

</Explanation>

</Mistake>

<Mistake>

## Expecting synchronous, instantaneous results {#convergence}

<Symptom>Results are "wrong" in the first rounds, or right after a change.</Symptom>

<Explanation>

Aggregate programs *converge*: information travels (at least) one hop per round, rounds are not synchronized,
and in its very first round a device has heard from nobody.

</Explanation>

<Explanation title="Fix">

Check results after the network had time to stabilize,
and design your program so that transient values are harmless.

</Explanation>

</Mistake>

<Mistake>

## Using non-stabilizing blocks where things change {#non-stabilizing}

<Symptom>Stale values that never go away after a device leaves or an input changes.</Symptom>

<Explanation>

Some blocks never forget by design: `share` with a monotonic operation (like `max`), `nonStabilizingGossip`, `everHappened`.

</Explanation>

<Explanation title="Fix">

Prefer their self-stabilizing counterparts (`gossipMax`, `isHappeningAnywhere`),
or wrap them in [`timeReplicated`](../explanation/standard-library/time-and-processes.mdx#replicated-processes).

</Explanation>

</Mistake>
